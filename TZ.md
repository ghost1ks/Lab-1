# Технічне завдання: StudyPlanner

## 1. Вступ
StudyPlanner — невеликий веб-застосунок, який допомагає студентам вести облік дедлайнів (лабораторні, курсові, іспити), бачити найближчі завдання та отримувати нагадування. Застосунок працює у браузері й не потребує встановлення.

## 2. Мета і задачі
- **Мета:** зменшити кількість пропущених дедлайнів за рахунок зручного обліку завдань і нагадувань.
- **Основні задачі:**
  - реалізувати додавання, редагування та видалення завдань з дедлайном;
  - відображати список завдань, відсортований за терміном, із підсвіткою прострочених;
  - реалізувати нагадування про наближення дедлайну;
  - забезпечити збереження даних між сеансами;
  - налаштувати версіонування та релізний процес.

## 3. Цільова аудиторія
Студенти університетів і коледжів, які одночасно виконують кілька робіт із різними термінами.

Ключові сценарії:
1. Студент додає завдання «Лабораторна №1», предмет, дедлайн і пріоритет.
2. Студент відкриває головну сторінку й бачить, що горить у найближчі 3 дні.
3. Студент позначає завдання виконаним, і воно зникає з активного списку.
4. За добу до дедлайну студент бачить нагадування.

## 4. Функціональні вимоги
1. **FR-1. Керування завданнями.** Створення, редагування, видалення завдання (назва, предмет, дедлайн, пріоритет, статус).
   *Критерій приймання:* після створення завдання з'являється у списку; після видалення — зникає; порожня назва не приймається.
2. **FR-2. Список і сортування.** Список завдань, відсортований за дедлайном, фільтр за статусом і предметом.
   *Критерій приймання:* завдання з найближчим дедлайном завжди зверху; прострочені виділені червоним.
3. **FR-3. Нагадування.** Показ повідомлення про завдання, дедлайн яких настає протягом 24 годин.
   *Критерій приймання:* завдання з дедлайном через 23 год потрапляє у нагадування, через 25 год — ні.
4. **FR-4. Збереження даних.** Дані зберігаються між сеансами (localStorage у v1.0, серверна БД у наступних версіях).
   *Критерій приймання:* після перезавантаження сторінки всі завдання на місці.
5. **FR-5. Експорт.** Експорт списку завдань у JSON (планується у v1.1).
   *Критерій приймання:* файл відкривається і містить усі активні завдання.

## 5. Нефункціональні вимоги
- **Продуктивність:** відображення списку до 500 завдань < 200 мс.
- **Безпека:** у v1.0 дані зберігаються лише локально; у v2.0 — авторизація через OAuth2 і HTTPS.
- **Сумісність:** сучасні браузери (Chrome, Firefox, Edge — останні 2 версії), мобільна адаптивність від 360 px.
- **Логування/моніторинг:** помилки виводяться в консоль; у v2.0 — серверні логи.
- **Доступність:** контрастність тексту не нижче WCAG AA, керування з клавіатури.

## 6. Обмеження та припущення
- Технології: HTML/CSS/JavaScript, Node.js > 18 для запуску тестів.
- Команда: 1 розробник, тому використовується спрощений GitFlow.
- Припущення: користувач має сучасний браузер і дозволяє localStorage.

## 7. Інтерфейс користувача (коротко)
Мікро-флоу:

```
Головна (список завдань) ──[+ Додати]──> Форма завдання ──[Зберегти]── Головна

            [галочка]── Завдання позначено виконаним
```

Головна сторінка: шапка з назвою, панель фільтрів, список карток завдань (назва, предмет, дедлайн, пріоритет), блок нагадувань угорі.

## 8. Архітектурні рішення (високорівневі)
- **Клієнт:** SPA на ванільному JavaScript, модулі `deadlines.js` (логіка завдань) і `reminders.js` (нагадування).
- **Сховище:** localStorage (v1.x), пізніше REST API + PostgreSQL (v2.0).
- **CI/CD:** GitHub Actions — запуск тестів на кожен push, створення реліз-артефакту при тегу `v*`.
- **Деплой:** GitHub Pages (статичний хостинг).


## 9. Критерії приймання
Загальні: всі пункти з `ACCEPTANCE_CHECKLIST.md` виконані.

Тест-кейси:
| № | Дія | Очікуваний результат |
| TC-1 | Додати завдання з порожньою назвою | Помилка валідації, завдання не створене |
| TC-2 | Додати 3 завдання з різними дедлайнами | Список відсортований за зростанням дедлайну |
| TC-3 | Завдання з дедлайном через 23 год | Потрапляє у нагадування |
| TC-4 | Завдання з дедлайном через 25 год | Не потрапляє у нагадування |
| TC-5 | Перезавантажити сторінку | Дані збережені |
